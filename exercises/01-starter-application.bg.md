# Упражнение 01 — Начално приложение, Git и първа промяна с AI

**Начална точка:** предоставеният от преподавателя начален код в `src/01`  
**Крайно състояние:** собствено Git репозитори с работещото приложение и една малка промяна по интерфейса, направена с помощта на AI; няма преход от състояние 00

## Задачи в час — създаване и стартиране на проекта

### Цел

Създайте собствено репозитори за MovieTracker, стартирайте подготвеното приложение и направете малка промяна с помощта на AI асистент. Целта е да упражните началния работен процес с Git, .NET и AI, без да добавяте нова backend функционалност.

### 1. Създайте собствено репозитори

- Създайте нова празна папка извън репозиторито с материалите за курса.
- Копирайте съдържанието на `src/01` в нея. В корена на новата папка трябва да се намира `MovieTracker.sln`.
- Копирайте и основния `.gitignore` файл, за да не добавяте генерирани файлове като `bin`, `obj` и `.vs`.
- Инициализирайте Git репозитори и направете начален commit:

```bash
git init
git branch -M main
git add .
git commit -m "Initial MovieTracker starter"
```

- Създайте празно отдалечено репозитори в GitHub, GitLab или друга използвана в курса платформа. Свържете го с локалното репозитори и изпратете началния commit:

```bash
git remote add origin <URL-НА-РЕПОЗИТОРИТО>
git push -u origin main
```

Преди commit проверете с `git status`, че не добавяте папките `bin`, `obj` и `.vs`.

### 2. Възстановете, компилирайте и тествайте решението

Изпълнете следните команди от корена на новото репозитори:

```bash
dotnet restore MovieTracker.sln
dotnet build MovieTracker.sln
dotnet test MovieTracker.sln
```

Всички подготвени regression тестове трябва да преминат успешно.

### 3. Стартирайте приложението

Стартирайте API проекта:

```bash
dotnet run --project MovieTracker.API --launch-profile https
```

Оставете го да работи и в друг терминал стартирайте Web проекта:

```bash
dotnet run --project MovieTracker.Web --launch-profile https
```

Отворете `https://localhost:7002/movies`. API работи на `https://localhost:7003`.

Ако локалният HTTPS сертификат все още не е настроен, изпълнете еднократно:

```bash
dotnet dev-certs https --trust
```

### 4. Разгледайте подготвеното приложение

- Проследете `GET /api/movies` от Blazor страницата през `MovieApiClient`, endpoint-а, handler-а, `IMovieRepository` и `InMemoryMovieRepository`.
- Намерете по един пример за class, record, enum, interface, dependency injection, LINQ и `async`/`await`.
- Обяснете отговорността на проектите Domain, Application, Infrastructure, API и Web.
- Променете номера и размера на страницата и наблюдавайте как pagination параметрите се валидират и прилагат.
- Разгледайте demo страниците и намерете `TODO` маркерите за функционалностите, планирани в следващите упражнения.

### 5. Направете малка промяна с помощта на AI

Използвайте AI асистент, за да направите една малка промяна само по представянето на страницата **Movies**. Подходящи примери са:

- промяна на заглавие или помощен текст;
- подобряване на съобщението при празен списък;
- малка промяна в подредбата или стила на съществуващ елемент.

В заявката си към AI посочете поне следните ограничения:

- промяната да засяга само страницата Movies и при нужда нейните стилове;
- да не се променя API договорът;
- да не се добавят CRUD операции, база данни, authentication, Docker или caching;
- да се запази съществуващото поведение.

Прегледайте предложението и diff-а, преди да приемете промяната. След това повторете `dotnet build` и `dotnet test`, стартирайте приложението и проверете резултата в браузъра. Направете отделен commit, например:

```bash
git add .
git commit -m "Improve Movies page presentation with AI assistance"
git push
```

Към предаването добавете използваната заявка към AI и едно-две изречения как сте проверили предложения резултат.

### Критерии за завършване

- Създадено е собствено Git репозитори и началният код е изпратен в отдалеченото репозитори.
- Решението се възстановява и компилира, а всички подготвени regression тестове преминават успешно.
- API и Web проектите се стартират, а страницата Movies показва подготвените филми.
- `GET /api/movies` връща твърдо зададените филми чрез `IMovieRepository`.
- Студентът може да обясни защо Web проектът не реферира server проектите.
- Малката промяна с AI е прегледана, проверена и записана в отделен commit.
- Не са добавени CRUD операции, база данни, authentication, Docker или caching.
